    How this stays current

    01

    Every merge redeploys

    Each merge to main rebuilds and redeploys the site through the Pages workflow. The build step records the commit and reads the versions above from Cargo.toml, Cargo.lock, docker-compose.yaml, the Jetstreamer submodule and the Three.js import map, so they always match main.

    02

    Pull requests are checked

    Pull requests that touch the site, its tests or the Rust and plugin sources run the site tests:

    • the configuration reference lists the same env vars and flags as the code, in both directions;
    • its YAML keys match FileConfig for superbank and superbank-verify;
    • every #[cfg(feature)] gate on an option carries its feature label;
    • every file a page cites exists;
    • the explorer and Alpenglow models follow their rules.
    03

    What is not automatic

    Descriptions, defaults, diagrams and the upstream references are written by hand from the sources above. CI catches renamed, added and removed options, but not a description that has gone stale.

    Found a problem?

    Please open a pull request with the fix. Each page's content lives in a few files:

    • Architecture explorer site/js/content.js site/js/topology.js
    • Alpenglow site/js/alpenglow-content.js site/js/alpenglow-model.js
    • This page scripts/site/build-info.mjs

    Run node --test "tests/site/*.test.mjs" before opening it; the same tests run in CI.
